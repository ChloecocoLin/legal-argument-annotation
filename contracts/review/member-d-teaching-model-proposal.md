# 第八批教学流程试行提案（待确认）

日期：2026-10-21。ED01–ED20 在现有全量契约中均为 PENDING_MODEL，未进入 READY；本提案不修改冻结 YAML 或生成 SDK。原《成员D分步开发计划》第十步明确要求“模型确认后实现”。

## 1. 建议的 D 分支试行范围

仅 local/test 非 prod。先接课程/班级及独立学生成员、作业、不可变标准答案版本、每次作答、评分规则版本、结果及教师反馈，使用同一 JDBC 事务和共同事实源。全部新教学写接口使用 /api/local/member-d/teaching；不冒充公共 ED 已冻结实现。

- Course/TeachingClass：教师所有权与班级各有 UUID；学生按真实有效 STUDENT 账号加入，成员可停用。只有本课程教师具有管理权，管理员不能默认跨课程读取标准答案和学生结果。
- Assignment：绑定课程/班级、发布时固定的标准答案版本、文本版本/范围、指南、练习类型、次数、截止时间及答案开放时间。已发布的题目/标准/评分版本不可原地替换；更新标准生成新版本，供新作业采用。
- StandardVersion：内容为独立冻结快照，保留来源和摘要。教师不能因角色而任取科研最终版；只可使用原任务创建者明确授权给该教师的 IN_DATABASE 教学来源。来源授权单独留痕，撤销后拒绝新建/发布，不回写既有教学快照。
- StudentAttempt：GET 只读、不创建草稿；首次/重新练习用显式 POST，新 ID 和 attemptNumber。本人有效课程成员才能读写；提交后保留独立完整内容，不能覆盖旧次作答或改写科研源。按作业锁与本人次数串行检查，重试不多占次数。
- ScoringRuleVersion/Result：固定标准版本、算法版本、各分项、适用性和来源摘要；历史结果保存不随新标准/规则变化。C 的五类专项只输出其现有关系/图专项分数，不擅自折算全课程总分。
- TeacherFeedback：仅所属课程教师可追加，保留作者、时间及版本；不覆盖学生作答。未开放时对学生隐藏，以免反馈透露答案。

## 2. 答案开放与独立作答

学生默认只取得题面、固定原文/范围和指南字典。标准答案、标准边界、标签、标准关系、图、评分差异和含标准内容的反馈，均须“本人已有一次正式提交且当前时间达到 answerOpensAt”后才返回。

RELATION_GUIDED 专项可在题目中提供固定命题/类型，用作 C 关系练习；必须明确标识，不把它当切割或完整案例独立练习。FULL_CASE 在提交/开放前不发标准要素及边界。其他课程、其他学生或未加入班级，即使猜中资源 ID 也拒绝。已公布答案后的重练是带答案练习，不冒充首次独立测评。

## 3. 评分口径及暂不完成项

复用 C TeachingScorer、RelationTemplateCodec 及 RelationMatcher/GraphAssembler，并使用快照局部 PropositionSource，不能使用演示全局 Mock。保留 C 的既有 SUPPORT/JOIN_VS_MATCH/ATTACK_VS_IDENTIFY/NESTING/GRAPH_COMPARE 专项权重与“不适用”处理，标明算法来源及版本。

B 分支目前未查到可接的边界/要素评分交付。FULL_CASE 的这些分项与综合权重在团队确认前保持 null/PENDING，不以“正确条数/总条数”等新公式冒充正式总分；总分不作未批准汇总。教师首页可展示真实完成数、已具备的专项维度与错误分类，明确不等于整门课程成绩。

成绩/标准样例归档导出须用独立教学来源与教师权限，不能通过 FINAL_ANNOTATION 绕过共享文件授权。其模型转正、完整边界/要素评分、班级趋势细化及正式导出列为后续接入项。

## 4. 实施与验收顺序

1. 核查并复用 C 的纯评分/图能力；建立六页路由、空态/只读模型边界及提案。
2. 提案获确认后，课程/学生范围 → 教学来源授权与冻结标准 → 作业发布/开放条件 → 本人每次作答/提交/次数门禁 → C 专项评分/封存结果 → 开放后的比对和教师反馈。
3. 测试越权、未开放服务端隔离、重复请求/旧版本/并发次数、不可变标准/作答/历史评分、无科研写入、原型页面与重启持久化。涉及完整总分和导出待冻结的部分继续明确门禁。

确认选项：允许按本提案在 D 分支试行，总分暂不汇总；或仅完成页面和只读评分适配，等待团队冻结持久化模型。
