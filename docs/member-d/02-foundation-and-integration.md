# 成员 D 基础实现与接入边界

## 持久化和迁移

本批次沿用 Java 17、H2/MySQL，不切换全队到 Java 21/PostgreSQL。Flyway 使用仓库 Spring Boot 管理的版本。生产数据库技术路线及既有公共模型问题需要团队统一。

- `db/migration/h2` 和 `mysql` 的 V1 保留 B 的旧指南表兼容布局；不执行 DROP TABLE。
- `db/migration/common/V2` 创建 D 的版本、快照、案级编号与事务回执表。
- `db/migration/dev` 只供 local/test：旧指南演示数据和独立的依赖桩存储。
- local/test 开启 out-of-order，避免 V900/V901 的本地场景阻止后续共享 V3+ 迁移；生产默认关闭。
- Spring SQL 初始化被禁用，旧 schema.sql/data.sql 不再由应用启动执行。
- 本地数据库是 `backend/.local-data/argument.mv.db`，重启不重建；文件加入忽略规则。
- 迁移清理被禁用，不自动 baseline 已有生产库。已有 MySQL 库应先备份和核对 V1，团队确认后采用显式接管迁移，不能自动删除或重建。

D 表使用复数 snake_case、UUID v4 身份、正整数 recordVersion。完整资源带创建/更新人和 UTC 秒精度时间。`VersionJson` 是公共元数据与 ID/时间/哈希工具；外部模块可复用同一约定。版本状态可变，快照内容单独保存，撤回不会更新快照表。内部快照同时保留图和布局，公开 V02 严格返回约定的四部分。

`annotation_case_counters` 使用数据库行锁分配案内连续版本号；SQL 唯一约束防止编号重复。提交复制完整资源、重映射参与项与布局引用、保存原对象来源，然后更新草稿状态和事务回执，全部同事务。失败时编号、版本、快照、草稿与回执一起回滚。

写请求按操作者、操作/对象、键做 24 小时幂等校验；同键同内容返回首次结果，同键异内容冲突。命中回执仍重新鉴权，先于过期 If-Match 检查。新增公共 AuditEvent 尚未冻结：内部 `annotation_mutation_receipts` 仅保存请求摘要、前后值、理由与首次结果，不能作为 L01–L03 已实现的声明，公共审计需后续接通。

## A/B/C 接入方式

后端 `AnnotationDependencies` 是内部服务边界：读取任务/范围/指南/草稿/对象，锁定共享父对象和草稿，保存草稿状态，以及检查历史裁定会话引用。正式适配器必须参与 D 的同一数据库事务；A/B/C 修改也需采用相同父记录锁顺序，不能在 D 开始快照复制时继续异步改草稿。远程无事务回调不能直接替换此边界，否则需另行设计原子性协议。

`VersionIdentity` 由 C 提供正式认证主体及当前权限。D 再检查 TaskMember、TaskAssignment、用户角色和任务/对象状态；版本主键和页面按钮不是授权依据。

当前只有显式 local/test 适配器。生产 profile 即使同时误设 local，也不会启用开发身份、预置依赖或本地上下文接口。正式 adapter 尚未提供时，prod 启动会因缺少这些依赖而失败，不静默退回固定 Token 或演示数据。

本地使用 `fixtures/member-d-ready-submission.json`：从共享 base/core 派生两人 ACTIVE 草稿的独立早期场景；保留原 UUID，预置 CONFIRMED 切割，无正式提交、裁定或最终结果。每个对象按类型+ID 存储，启动仅在空依赖库时装载，不覆盖已有数据；complete/validation 不作数据库种子。生成脚本不会修改共享 Mock。

`/api/local/member-d/context` 和 `/drafts/{draftId}` 只用于本地有权限的依赖预览，不冒充 A01/T03/E01/R01/GR01 等公共接口。前端正式预览需在 A/B/C 接入后替换适配器；任务列表、本人编辑工作台和真实认证也仍由对应成员交付。

## 校验责任

D 的提交边界强制：文本哈希及 UTF-16 精确切片、无遗漏重叠、绑定一致、动态标签类别、P 编号、已确认切割、当前草稿所有权、同快照参与项、S/A/M 二元及 J/I 多元规则、自引与循环拒绝、M 的个别/一般端点、逻辑图覆盖。

这些是防止非法快照入库的结构检查，不替代 C 的关系语义判断、图元绘制和完整质量算法。没有擅自实现一致性算法；一致性关口使用预置数据，S04/S05 仍待确认。统一切割后任意边界偏离缺 M10/M13 变更理由模型，当前安全拒绝，不伪造 Non-O 或偏离原因。

撤回必须由本人有效分配执行、版本为 SUBMITTED、任务仍工作中且未被任何历史裁定会话引用。保存理由，保留原版，将原草稿恢复 ACTIVE 并递增版本；存在另一份 ACTIVE 草稿时拒绝，避免破坏每案每人最多一份活动草稿约束。后续提交产生下一 Vn。

## 仍需团队统一的旧基础差异

B 的兼容指南表仍使用单数表名、部分旧演示 ID 和 recordVersion=0；本批次不把这些改动扩散到 B 的数据和 DTO。旧公共指南的并发/幂等、RBAC 和操作者审计也未整体补齐。新增 D 域遵守规范，旧模块的整体迁移需评审与联调。

MySQL 提供了兼容迁移和依赖，当前实际执行验证使用 H2。未宣称生产 MySQL、正式认证、全队共享事务或完整科研链已通过。
