## 已实现与页面对照

- FV01 从当前生效决定生成独立最终快照，复制要素/关系/参与项，生成新 ID，重映射所有内部引用，按原文重排 P 编号，保存采纳及排除来源。原始 Vn 内容和对象 ID 不变，仅更新流程状态为 ADJUDICATED。
- FV02 保持冻结摘要响应；FV03/FV04/FV05 保持冻结响应与严格请求字段。完整页面通过 /api/local/member-d/final-review 的只读组合适配器读取，prod 不加载；FV02 完整传输建议单独存放于 review 文档，不修改冻结输入或生成物。
- DRAFT → IN_REVIEW → APPROVED，以及 IN_REVIEW → DRAFT。所有写入使用幂等、资源 If-Match、案例锁与同一事务；永久记录生成/送审/退回/批准轨迹。旧快照不因状态转换而改写内容。
- 下一版本号由客户端按契约提交，服务端只接受案例下一连续编号；并发同一编号返回同一既有资源，避免重复最终版。仅退回草稿后可重建下一快照，旧版变为只读。APPROVED 禁止继续编辑、退回或新建替代版。
- /final-review 与 /final-review/:finalVersionId 对照 final-review.html：1.7:1 双栏、要素表、关系清单、图区域、文档信息、裁定摘要、质量检查；补充来源展开、排除记录及审查轨迹。裁定页和侧栏提供入口。
- 工作图按真实 participants 生成，支持每个独立连通结构、孤立命题切换及缩放。明确标注“工作视图 · 结构预览”，不代替 C 的正式图组件；PNG 和正式视图保持禁用。

## 正式批准门禁与依赖

FinalReviewDependencies 是内部适配端口，不是新公开契约。resolve 必须消费 B 的已冻结 M13 映射、自定义不可变快照和 C 的统一关系映射。当前本地适配器仅支持一对一的采用/一致确认/删除，自定义和拆分合并仍明确拒绝。

D 在生成及审查时校验全部采纳/排除来源、生效决定与来源对象归属；采用和一致结果不能改变原始文本/标签。送审再次检查固定文本哈希、UTF-16 切片与完整范围、动态标签、命题编号、关系字典、S/A/J/M/I 参与项、嵌套和环、全部图结构覆盖，以及专家待办。基础关系检查复用 SubmissionChecks 的结构校验，不重复实现 C 的完整语义算法。

本地 assess 永远 formalReady=false、mode=LOCAL_PREVIEW；只能联调送审和退回，服务端 FV05 也拒绝批准。没有通过环境变量、客户端字段或勾选绕过的开关。正式实现必须提供绑定本快照/决定/指南的实时验证证据，且 mode=PRODUCTION；当前没有生产 fallback。即便端口返回 ready，D 的来源、结构和专家检查仍须通过。证据须匹配 canonical immutable snapshot 的 SHA-256、当前 decisionDigest 与 guideVersionId；工作流状态/时间不参与内容摘要，过期或跨内容证据被拒绝。

批准路径仅在自动化测试中用服务端测试替身验证。它不是正式 C 验证已接通。APPROVED 始终 committedAt=null；任务仍 IN_PROGRESS、会话仍 FINAL_REVIEW，不能宣称入库或取得科研导出资格。本批不实现 FV06/EX 接口。

## 仍待确认的业务边界
