## 三、共同接入规则

1. 继续以指南及《接口与数据格式约定》为准。分支实现冲突时形成小范围兼容补丁，不以较新分支天然覆盖规范。冻结 YAML 和生成 SDK 继续保护，批准后同步 Markdown、完整/READY YAML、Mock 并重新生成。
2. 先统一身份、案例/对象身份及数据读取，再开放写入。C 为登录主体来源，A 的 AuthContext、B 的 CurrentUserProvider、D 的 VersionIdentity 接同一主体，清除真实模式下默认演示身份和可伪造身份头。
3. 一种业务事实只保留一个权威写入来源。D 的不可变快照不回写；A/B/C 通过仓库/投影接口读取。联调可临时有显式 Mock profile，但不在两个数据库之间用 HTTP 连续写来冒充同事务，也不长期双写两份会话/要素。
4. 保留现有 H2/MySQL、Java 17 和 D 的 Flyway 路线作为本分支实施起点；对 A/B/C 的增量表逐一做可重复迁移。禁止把它们 `sql.init.mode=always + DROP TABLE schema.sql` 直接带进当前持久化库。最终公共表归属及兼容结构按规范评审确定，不擅自切换全队数据库。
5. 数据适配集中处理六公共字段、recordVersion 初始 1、UUIDv4、UTC 秒精度、UTF-16、ownerType/ownerId、动态指南和参与项。B/C 中的 recordVersion=0、LocalDateTime、旧演示 ID 等逐项解决；不改写已冻结源 ID 来让示例强行匹配。
6. 统一案例父锁和数据库事务，业务状态与必要审计/幂等结果原子提交。复核“先查版本再 update”的路径是否实际阻止并发覆盖，而非只看有 If-Match 参数。
7. 前端在当前原型布局上按区域替换组件：原文/边界用 A、类型/命题自定义用 B、关系/图用 C、流程/最终/导出用 D。保留单一工作台、单一裁定入口；合并路由/公共请求层和用户状态，不能整份覆盖各分支文件。

## 四、新执行顺序

### 第一批：统一基础与最小接入骨架（原第 1、2、12 步）

目标：在 D 分支接入 A、B 最新累积、C 的必要模块，得到可启动且不重复路由/表/身份的联合骨架。

- 固定三个来源 SHA，先做文件与路由/Bean/表结构冲突清单；B 只取 expert-review 累积成果。
- 接 C 登录、会话恢复、登出及前端路由守卫；建立统一 Actor 和权限码/角色映射，保留对象范围校验。
- 优先接 A 的文书、文本、范围、任务、成员、分配读取与原型页面；将内存仓库替换为可加入共享事务的持久化仓库，兼容保留已有 D 运行数据。
- 统一 B/C/D 会话、版本、Element、关系参与项与图的读取契约，区分冻结快照与编辑对象，不为迁就旧 Mapper 重复创建事实。
- 将初始化 SQL 改成增量迁移/隔离样例装载，解决 recordVersion、时间、用户 ID/成员 ID 混用；T13 等重叠路由只有一个正式实现。

验收：空库/已有库均可启动，重启不丢新增任务；真实登录后能按授权读任务及文书；相同案例 ID 在 A/B/C/D 中指向同一业务对象；原 D 回归继续通过。此批不开放最终批准。

### 第二批：接通真实切割、本人草稿、提交与撤回（原第 3、4、6 步）

- A 的 S01–S03 作为独立输入入口，接 D 的计算与 S04/S05 试行模型；保持用户确认的全部两两内部边界 F1 平均、未舍入值严格 >0.8。
- 明确审核退回、替代提交和成员失效后的有效输入集合；计算记录固定输入、算法版本与文本摘要，旧记录可复算。
- 统一关口落库后创建/绑定本人草稿，接 A 原文、B 类型编辑和 C 关系编辑。先核对普通草稿 API，再补真正缺失的保存能力，不复制裁定者 J10。
- 适配 C 的 PropositionSource、草稿归属和 RelationLookup，读取同一草稿实体；正式路径移除 mock_draft/mock_proposition 依赖。
- A04 复用 C 校验并冻结完整新 Vn，A05 按当前门禁撤回；A 的任务详情使用 D 的 T13，直接显示 X/N 和本人提交入口。

验收：新建真实任务后，至少两名不同账号从独立切割开始，完成普通草稿→完整提交；第三名标注员及撤回/补交数量正确；重启、并发、盲标隔离、关口变更均正确。不能只用预置草稿验证。

### 第三批：命题裁定、自定义与专家回流（原第 5、6 步）

- B 的 J03 查询/候选展示接 D 的 J01/J02 固定来源会话；完善真实命题和非命题对齐，不按跨版本 P1 直接认同对象。
- 接 B 的 J09/J10，打通“保存独立自定义快照→返回当前冲突项→另行保存 J04 决定”；补 D 对自定义结果的消费与来源覆盖。
- 冻结统一命题结果和持久化映射，向 C 提供 unifiedSnapshotId / PropositionMappingSource；先验收可表达的一对一，再按评审模型处理拆分、合并、排除和非命题。
- 接 B 的 J12/X01–X05 和两专家页面，身份及指派改为真实任务成员；保存来源阶段，结论和指南依据齐全后回到原阶段，不把 CONFIRMED 当作自动裁定完成。
- 校准公共字段、乐观锁、幂等和共同事务；未决专家、未确认一致项继续阻止 J05。

验收：真实 Vn 可查询候选；J10 新 ID/来源可读而原版本不变；采用、自定义、删除、一致确认及命题专家回流均进入有效决定。拆分合并若仍无正式模型，单列门禁，不默认通过。

### 第四批：关系裁定、完整图和正式验证适配（原第 5、7 步）

- 用真实统一映射替换 C 的 MockPropositionMapping；当前 Map<String,String> 无法表达的复杂拆分合并须按已评审模型扩展，不能任取一个端点。
- D 在 J05 事务中调用 C 的比较能力建立关系项，保留 J06 查询；避免 C 的惰性建项与 D 创建两次。D J07/J08 消费 C 的语义校验和纯结果计算。
- 完成关系自定义的 J10 分支（仍由 B 唯一维护），接 C 结构校验；扩展 B 的 RELATION 专家问题及关系阶段回流。
- 用 C 的 ArgumentGraph/GraphAudit 替换 D 的临时图预览，读取全部结构及孤立命题；图布局与逻辑关系独立。
- 建立冻结快照的只读验证适配：纯 RelationValidator/GraphAssembler + D 来源/文本/全覆盖规则，不在最终审查读操作中 upsertGraph。GR02 的 warning/VALID 不能直接当最终批准证据。

验收：命题未完成不能关系裁定；删除内层关系后的悬空外层会阻止提交；跨版同名编号、多图/孤立命题、嵌套与环、关系专家未决均覆盖。正式证据须绑定当前内容、指南和决定摘要，不能改一个 formalReady 常量解锁批准。

### 第五批：最终审查、补正、入库与 T14（原第 7、8 步）

- 通过真实自定义/专家/关系映射生成独立最终快照，保留采纳及排除来源；按评审传输补齐 FV02 完整读取，逐步退出 local 工作区读取。
- 独立 CorrectionRound 接入新 B/C 决定/图，重新验证映射及专家条件；保留旧会话/旧内容，不能只换编号后重建同结果。
- 真实数据和正式证据下验收 FV03/FV04/FV05，再接 FV06 原子入库；审核模型、永久审计及生产配置按提案共同评审后转正。
- 复用 A 的 T14 实际建任务逻辑，读取 D 当前入库最终版，校验源任务与版本归属，双来源和新任务原子保存。旧任务/最终版保持只读。
- U08、成果列表、分布和真实计算统计改读共同事实源，消除跨模块数量不一致。

验收：完整真实科研链可批准并唯一入库；任何写入口都不能改已入库数据；重标创建新任务且双来源可追溯；多案例任务锁定范围、回滚和重启持久化正确。

### 第六批：结构化导出回验及 PNG/SVG 归档（原第 9 步）

- 先用第五批的真实入库成果回验现有 JSON/XLSX，检查不同指南、来源、专家/自定义结果、复杂参与项及长文本。
- 复用 C 图渲染与导出算法，补受控生成/提交机制，并绑定最终快照摘要、渲染版本与全部结构清单；浏览器直接下载只作为预览导出，不能冒充已归档科研文件。
- 将生成字节纳入 D 的不可变 FileAsset、ExportRecord 和短时下载凭证，服务端验证来源/格式/大小/摘要；不把任意客户端上传标为“正式图”。正式方案（受控浏览器渲染或等价服务器渲染）需评审后确定，不假定仓库已有后端图生成器。
- A/B 附件按真实业务归属接统一文件服务；创建者原件仍走 A 的待审提交。导入映射、额外格式、批量多文件打包继续登记契约扩展。

验收：真实 IN_DATABASE→文件→记录→下载追溯；PNG/SVG 覆盖所有结构和孤立命题；重复 GET 不写审计；已有文件不覆盖；APPROVED/越权/伪造图文件不能导出。

### 第七批：自动任务（原第 11 步，可在主线等待评审时穿插）

M01–M04 管理持久化状态、模型版本与执行适配；核对 B 是否实际提供 M05/M06，缺少则先做契约与明确测试适配，不把已有人工 J10 当自动建议审核。仅授权创建者管理，机器候选不计入 X/N、不直接成为最终来源。

### 第八批：教学全流程（原第 10 步）

优先复用 C 已有关系/图专项练习和 TeachingScorer，B 的类型组件与 A 文本/任务能力。先评审课程/作业/答案/每次作答/评分规则版本及开放隔离，再接六个原型页面、分项评分和 D 汇总。C 的专项权重不自动成为整套课程总分公式；缺少的边界/要素评分、教师反馈、班级和趋势分析单列补齐。

### 第九批：最终联合验收与交付（原第 12 步贯穿执行）
