## 实现与来源

- 复用 C `ab6f03d` 的 RelationRules、RelationValidator、RelationLookup、关系投影实体/DTO、GraphAssembler 和 SVG ArgumentGraph/几何组件。仅引入需要的纯引擎和前端组件；未导入 C 的 mock_draft/mock_proposition、Mapper 写入或初始化 SQL。
- `StructureEngine` 对同一草稿的一批要素、关系、参与项建立只读作用域，调用 C 的规则与装配器，并补匹配组合全部叶节点均为个别判断的检查。禁止跨草稿、非命题参与、错误方向/矩阵、重复目标、自引用和嵌套循环；不自动补传递支持。
- R01–R04 使用共享事实、案例父锁、同事务回执和严格 READY 投影。R03 检查关系 recordVersion，整组替换参与项并保留旧事实；R04 保留 REMOVED 关系且禁止删除仍被外层关系引用的内层关系。
- GR01 只读，未生成图返回 404；GR02 由用户显式触发，带当前草稿版本，检查全部命题/关系集合及完整文本覆盖，持久化真实 VALID/INVALID；GR03 追加布局版本，不修改逻辑。已有不兼容布局保留为历史，但不进入当前图和新冻结版本。
- A04 在提交事务中再次执行 C 引擎及 D 的固定文本/指南/覆盖/归属检查。版本中要素、关系、参与项、图和布局均分配独立新 ID，引用同步重映射；旧版内容不随撤回或补交而变化。
- 真实 S01 案例提交必须引用当前唯一确认关口。旧显式试行案例的历史示例关口仍保留，仅通过独立兼容路径识别其试行关口，不改写历史记录。
- 为“已生成图后需要删除分类”增加显式内部命令 `/api/v1/integration/drafts/{id}/reset-graph`：检查本人权限、版本及幂等，将旧图/布局保留为历史，解除当前草稿图引用后重新编辑。该辅助命令不是 READY GR 接口的替代；正式公共化仍需接口评审。
